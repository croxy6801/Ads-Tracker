1. Multi-Provider API Integration Layer

The API integration layer connects to major ad networks via isolated, read-only adapter clients. Each adapter implements a standardized interface (BaseAdProviderAdapter) that abstracts vendor-specific pagination, token refresh, and rate-limiting protocols.

1.1 Google Ads API Integration (v16)

Connects using OAuth 2.0 with the read-only scope (https://www.googleapis.com/auth/adwords). Queries metrics via the Google Ads Query Language (GAQL) streaming endpoint. 

# GAQL Query for Daily Campaign Metrics
SELECT
  campaign.id,
  campaign.name,
  campaign.status,
  segments.date,
  metrics.cost_micros,
  metrics.impressions,
  metrics.clicks,
  metrics.conversions,
  metrics.conversions_value
FROM campaign
WHERE segments.date DURING LAST_30_DAYS
  AND campaign.status = 'ENABLED'
  • Currency Normalization: Google reports cost in micro-units (1/1,000,000 of account currency). The adapter converts cost_micros directly into integer cents: spend_cents = cost_micros // 10000.
  • Attribution Window: Google Ads default 30-day click-through attribution is captured with daily snapshot revisions.

1.2 Meta Marketing API Integration (Graph API v19.0)

Queries Meta’s /act_{ad_account_id}/insights endpoint with read-only access token permissions (ads_read). 

GET /v19.0/act_{account_id}/insights?
  level=campaign&
  fields=campaign_id,campaign_name,spend,impressions,clicks,actions,action_values&
  time_increment=1&
  date_preset=last_30d
  • Action Parsing: Meta represents conversions in an array of action dicts. The adapter extracts actions matching action_type == 'purchase' or configured lead event IDs.
  • Currency Normalization: Meta returns spend as a float string (e.g. "142.50"). Normalized via int(round(float(spend) * 100)) to guarantee integer precision.

2. Data Ingestion & Normalization Pipeline

The ingestion pipeline harmonizes raw API payloads into strongly-typed Pydantic records and stages them for downstream statistical calculation.

======================================================================================================== DATA INGESTION PIPELINE ======================================================================================================== +-------------------+ +-------------------+ +-----------------------+ | Google Ads API | | Meta Graph API | | Virtual Simulator / | | (GAQL Stream) | | (/insights REST) | | CSV Upload Source | +-------------------+ +-------------------+ +-----------------------+ | | | +---------------------------+-----------------------------+ | v +---------------------------------------+ | Ingestion Dispatcher | | - Token Refresh & Rate Throttling | | - Idempotency & Signature Hash Check | +---------------------------------------+ | v +---------------------------------------+ | Normalization & Validator | | - Pydantic v2 Unified Schema Parsing | | - Currency Conversion (to cents) | | - Date & Timezone Alignment (UTC) | +---------------------------------------+ | v +---------------------------------------+ | Attribution Lag Filter (72h) | | - Tag is_mature = FALSE for t-2..t0 | | - Tag is_mature = TRUE for <= t-3 | +---------------------------------------+ | v +---------------------------------------+ | PostgreSQL Persistence | | UPSERT into daily_metrics table | +---------------------------------------+

2.1 Idempotency & Upsert Strategy

Ad platforms continuously revise metrics for recent days as delayed conversions arrive. The pipeline executes atomic PostgreSQL UPSERT queries anchored by the composite primary key (campaign_id, date): 

INSERT INTO daily_metrics (campaign_id, date, spend_cents, impressions, clicks, conversions, is_mature)
VALUES (:campaign_id, :date, :spend, :impressions, :clicks, :conversions, :is_mature)
ON CONFLICT (campaign_id, date) DO UPDATE SET
  spend_cents = EXCLUDED.spend_cents,
  impressions = EXCLUDED.impressions,
  clicks = EXCLUDED.clicks,
  conversions = EXCLUDED.conversions,
  is_mature = EXCLUDED.is_mature;

4. Core Logic for Performance Metric Calculation

4.1 3-Day Rolling Maturity Filter

Any metric record where $\text{Record Date} > \text{Current Date} - 3\text{ days}$ is marked is_mature = False. All analytical aggregations strictly filter on WHERE is_mature = TRUE.

4.2 Bayesian Beta-Binomial Evaluation

Conversion rates ($CVR = \text{Conversions} / \text{Clicks}$) are modeled using a conjugate Beta distribution: 

  Prior: Beta(α_0, β_0)  [Informed by historical target benchmark]
  Posterior: Beta(α_0 + conversions, β_0 + (clicks - conversions))
  Confidence = P(Posterior CVR < Benchmark CVR | Data)

A campaign is only classified as Underperforming when: $$P(\text{Mature CPA} > 1.25 \times \text{Target CPA}) \ge 0.80 \quad \text{AND} \quad \text{Mature Days} \ge 7$$

4.3 Capital Waste Quantifier Formula

Capital waste represents spend that yielded conversions at costs exceeding the allowable target CPA: $$\text{Realized Waste} = \sum_{t \in \text{Mature}} \max\Big(0,\; \text{Spend}_t - (\text{Conversions}_t \times \text{Target CPA})\Big)$$
