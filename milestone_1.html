1. Executive Overview & Architectural Philosophy

Digital marketing teams on Google Ads, Meta Ads, and LinkedIn Ads collectively lose 15% to 35% of their monthly spend on underperforming campaigns due to two core human fallacies: premature budget slashing during early attribution lag, and prolonged inaction while waiting for ambiguous dashboards to clarify.

Ads Tracker solves this through rigorous statistical design, real-world attribution modeling, and a strictly read-only, human-in-the-loop governance structure.

Core Design Invariants (Non-Negotiables)
  1. Evidence Before Advice: Never issue a pause or shift recommendation until the 3-day maturity lag window has closed and statistical confidence exceeds ≥ 80%.
  2. Read-Only by Design: Zero write-back access or automatic account execution. Recommendations produce human-executable shifts (Approve, Snooze, Dismiss).
  3. Conservative 25% Reallocation Protocol: Budgets shift exclusively in 25% tranches with mandatory 7-day re-evaluation windows to detect audience saturation.
  4. Constructive Funnel Rehabilitation: Underperforming campaigns provide actionable remediation (Creative, Audience, Funnel, Bidding) before recommending budget deprecation.

4.1 Component Roles & Data Pipeline

  • Ingestion Pipeline: Ingests heterogeneous reporting outputs from Google Ads API (search, display, pMax) and Meta Graph API (feed, stories). Maps divergent cost schemas into uniform integer-precision micro-units.
  • Maturity Filter: Intercepts raw metrics and tags records younger than 72 hours as is_mature = FALSE. Prevents premature statistical evaluation during attribution lag.
  • Bayesian Analytical Engine: Employs a conjugate Beta-Binomial model to compute the posterior distribution of conversion rates and CPA against benchmark goals.
  • Simulator Engine: Provides an on-demand virtual simulation loop generating real-time calendar ticks, realistic spend volatility, and progressive attribution maturation from Day 0.

5. Unified Data Schema for Cross-Platform Metrics

Different ad platforms use disparate naming conventions, attribution delays, and data representations. The unified schema harmonizes all sources into a single source of truth.

5.1 Cross-Platform Field Harmonization

Unified Field Google Ads API Meta Marketing API Data Representation & Normalization
spend metrics.cost_micros spend (float string) Stored as cents / smallest currency unit (integer) to eliminate floating-point rounding errors.
impressions metrics.impressions impressions Integer count of visual impressions served.
clicks metrics.clicks clicks / inline_link_clicks Integer count of outbound user clicks.
conversions metrics.conversions actions[action_type='purchase'] Decimal(10,2) or Integer count of attributed conversions.
revenue metrics.conversions_value action_values[action_type='purchase'] Stored as currency cents; used for ROAS computation.
is_mature Derived ($\text{Date} \le \text{Now} - 3\text{d}$) Derived ($\text{Date} \le \text{Now} - 3\text{d}$) Boolean flag isolating data subject to attribution lag.

5.2 Relational Entity-Relationship DDL (PostgreSQL)

-- 1. Campaigns Definition Table
CREATE TABLE campaigns (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    org_id UUID NOT NULL,
    name VARCHAR(255) NOT NULL,
    platform VARCHAR(50) NOT NULL CHECK (platform IN ('google_ads', 'meta_ads', 'linkedin_ads', 'simulator')),
    target_cpa_cents BIGINT NOT NULL,          -- e.g., 120000 = ₹1,200.00
    daily_budget_cents BIGINT NOT NULL,
    status VARCHAR(30) NOT NULL DEFAULT 'collecting_data',
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 2. Daily Time-Series Metrics Table
CREATE TABLE daily_metrics (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    campaign_id UUID NOT NULL REFERENCES campaigns(id) ON DELETE CASCADE,
    date DATE NOT NULL,
    spend_cents BIGINT NOT NULL DEFAULT 0,
    impressions INT NOT NULL DEFAULT 0,
    clicks INT NOT NULL DEFAULT 0,
    conversions INT NOT NULL DEFAULT 0,
    revenue_cents BIGINT NOT NULL DEFAULT 0,
    is_mature BOOLEAN NOT NULL DEFAULT FALSE,
    CONSTRAINT unique_campaign_date UNIQUE (campaign_id, date)
);

-- 3. Daily Analytical Snapshots
CREATE TABLE analysis_snapshots (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    campaign_id UUID NOT NULL REFERENCES campaigns(id) ON DELETE CASCADE,
    snapshot_date DATE NOT NULL,
    mature_spend_cents BIGINT NOT NULL,
    mature_conversions INT NOT NULL,
    mature_cpa_cents BIGINT,
    bayesian_confidence NUMERIC(5, 4),        -- e.g., 0.9425 = 94.25% confidence
    status VARCHAR(30) NOT NULL,
    estimated_waste_cents BIGINT NOT NULL DEFAULT 0,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 4. Recommendations & Human Governance Log
CREATE TABLE recommendations (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    from_campaign_id UUID REFERENCES campaigns(id),
    to_campaign_id UUID REFERENCES campaigns(id),
    reallocation_pct INT NOT NULL DEFAULT 25,
    daily_amount_cents BIGINT NOT NULL,
    rationale TEXT NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'approved', 'snoozed', 'dismissed')),
    decided_at TIMESTAMP WITH TIME ZONE,
    decided_by VARCHAR(255)
);
